# 让用户先完成任务，再按需理解 TOMC

项目定位依据主论文：**长上下文大模型的记忆表示**。MCP 持久化与助手接入提供保存、取回和上下文交接。[原文与实现来源核对](../docs/paper_scope.md)。

本轮将默认使用路径从“选择算法并查看 ledger”改成“提供历史与下一步任务，拿走可用上下文”。论文图组、原有编译 API 与研究工作台保留，但不再是第一次使用的前置要求。

## 2026-10-02 实际试用记录

核对版本：GitHub 主分支 `ea6b15e`，HF Space `1a8a236d72bb3523855290d813272988637dcfef`。重点入口代码及发布清单一致。使用真实 Chromium 分别操作本地界面和运行中的私有 CPU Space；输入均为合成内容，没有调用付费 reader，也没有修改助手配置。

| 实际操作 | 结果 |
|---|---|
| 粘贴历史、填写任务、生成上下文 | 本地和线上均完成；线上此次首次页面就绪约 3.0 秒，短示例生成约 0.8 秒，为单次观察 |
| 中文 JSONL 上传 | 消息角色和中文文本保留，能够生成上下文 |
| 复制 | 浏览器剪贴板与生成文本完全一致 |
| 来源检查与状态快照 | 可以展开来源；更新后 `drink=water`，先前副本仍为 `tea` |
| 论文结果 | 可以切换到 1M；三 reader 的配对结果可读 |
| 桌面与手机 | 1440、390、320 px 没有页面横向溢出；宽研究表在面板内滚动 |
| 未登录的在线入口 | 返回 404；Space 为私有，需要 HF 的相应访问权限，GitHub 仓库协作者权限不能替代 |

发现的实际摩擦：

1. **过期结果重新出现。** 生成期间修改任务，原先的清空操作可能被晚到的旧响应覆盖。本地和线上均复现。修复后，服务端结果先进入隐藏接收区，浏览器核对历史、任务和记忆长度后才显示；不匹配的响应跳过更新。另用刻意延迟 2 秒的旧请求验证，新结果仍保留。
2. **首次试用需要找到折叠区。** 原流程要展开、载入、再生成。现在首页提供“一键试用”，直接载入示例并生成；任务输入框也提供中英文示例。
3. **空输入反馈主要是英文。** 为缺失任务、缺失历史和超长输入增加中文恢复提示。
4. **长段落可能生成空记忆。** 一条 7,812 个估算 token 的原文行，在最大 4,096 档下仍无法完整装入。原来只提示增加长度；现在说明按句添加换行或调大长度，最大档仍需分行。当前完整原文行的打包约定保持不变，尚未增加自动分句。

仍需改善的产品体验：复制按钮较小；从网页继续调用模型仍需手动交接；助手接入需要终端安装和配置。长文本固定规则路由也受任务措辞影响，例如 `current` 与 `now` 未必选到同一路由。界面顺利生成不代表任意任务上的答案准确；正文实验和网页机制演示应继续按各自口径理解。

本轮修复在独立评审分支，尚未合入主分支或部署到 HF。108 项测试及更新后的浏览器检查通过；核心编译算法和论文实验数据没有改变。上述实测不能替代独立用户的首次体验访谈。

## 已落地的三种入口

| 用户 | 默认动作 | 产品替用户处理什么 |
|---|---|---|
| 想在现有聊天模型里继续工作 | 粘贴文本 / 上传文件 → 填任务 → 复制结果 | 输入适配、方法选择、任务与上下文拼装 |
| 常用支持本地 MCP 的助手 | 一次接入 → “保存笔记” → 下次“取回继续” | 本地持久化、按笔记本隔离、按下一步任务准备记忆 |
| 开发者 | `prepare_context(history, task).messages` | 自动入口与 provider-neutral 消息；需要时查看 `.compilation` |

短历史放得下就完整保留。较长历史由 hybrid 规则选择带原文的任务记录或 BM25 来源检索，不把自然语言包装成未经验证的结构化状态。MCP 提供 prepare、remember、recall、list、forget 五个工具，方法语义沿用现有实现。

## 减少摩擦的具体处理

- 普通使用不展示必选算法、估算单价或来源表。
- 接受普通文本、消息 JSON、JSONL 和明确支持的文本块；无法识别的多模态块报错，不悄悄丢弃。
- 输出已经附带当前任务，可复制给模型；复制按钮按真实浏览器剪贴板内容核对。
- 修改输入立即清空旧输出；小屏生成后滚到结果位置。
- 调整后的主按钮在桌面、390px 和 320px 首屏可见。
- “用完再了解原理”折叠区域提供方法原因和证据。原有 tour、工作台与论文结果继续可访问。
- 接入配置自动使用当前 Python 的绝对路径，不让用户猜测虚拟环境地址；输出配置供合并，保留用户现有设置。

## 工程验证与尚未验证的部分

本地验证覆盖 102 项测试、真实 MCP 子进程的保存 / 重启取回 / 隔离 / 删除、两个旧协议版本的初始化与工具调用，以及浏览器上传、复制、旧结果清空和移动布局。标准 MCP 接口不等于已经在每个客户端 GUI 中完成安装测试；助手是否主动调用和回答效果也仍需真人私测。

这次没有配置当前作者的助手，也没有发布公开插件市场条目。MCP 只保存明确传入工具的内容，不能读取其他聊天，也不能自动替换宿主的内部记忆。托管 Demo 不提供共享持久化笔记本。GitHub/HF 保持私有，因此外部用户仍需获得访问权限后才能安装。

## 下一轮私测任务

让用户从 [接入说明](../docs/assistant_setup.md) 自行完成一次安装，随后不给额外指导：

1. 用自己的文本生成上下文并复制到原有模型。
2. 让助手保存一份研讨会笔记，在新聊天里取回并继续。
3. 找回笔记本名字，删除指定笔记本，确认其他笔记本不受影响。

记录完成时间、失败步骤、是否需要解释术语、是否误以为自动读取全部聊天。优先修复实际失败步骤。云端一键接入与框架自动注入需要额外的身份、数据隔离和宿主集成工作，不能当成本轮已实现能力。
