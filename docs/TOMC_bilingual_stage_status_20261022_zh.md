## 用户最后确认的分档规则

用户明确选择按单次上下文长度分档，取代累计成长。源码已完成：

| 本次待压缩上下文的估算输入 token | 阶段 |
|---|---:|
| 小于 10,000 | 1 |
| 10,000 至小于 100,000 | 2 |
| 100,000 至小于 1,000,000 | 3 |
| 至少 1,000,000 | 4 |

下一次输入较短时允许降档，保持原有四套素材与动作。累计节省、费用、整个 JSON 请求大小都不决定阶段。长度未知时显示中性状态，不播放假定档位的压缩动画。

`context_input_tokens` 单独记录真正交给编译器的上下文输入量。网关在 CPU 编译完成时发布此数字，小猫立即据此播放；模型随后返回用量不再重复播放。同一队列内每条上下文使用各自长度。旧 MCP 写入和统计口径保留兼容；旧网关记录缺失正文长度时不猜测。

这些最新源码改动发生在桌面控制被中止前后，**尚未部署到运行进程**。不要把已安装的双语界面与已启用的单次分档混为一谈。
