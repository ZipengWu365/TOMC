# TOMC 的单次与累计 token 统计

2026-10-18 桌面展示更新：小猫主面板与单次气泡显示“预计少花”美元，原始 token 和百分比放在详情。点击「估价」选择宿主、参考模型、计价档位及缓存/未缓存输入，并查看核验时间和来源。每次桌面安装同步 OpenAI、Claude、DeepSeek、Cursor 官方费率；断网保留旧费率及原核验日期。当前本机参考模型为最近活动 Claude Code 会话的 Opus 5.5，未缓存输入 $4/百万 tokens；以所选模型单价折算全部准备记录，**不是历史每次调用的实付汇总**。Cursor Auto/未知模型不猜测单价；Cursor 展示基础参考价，不包含套餐或附加费。完整口径见 `src/tomc/cost_estimate.py`、`pricing_catalog.py` 和根目录 `CURRENT_PET.md`。缓存变化、额外请求开销、输出变化与订阅计费不能从减少的文本量推断。

首次达到皇冠阶段会播放约 10.5 秒的绿洲庆祝，可点击收起；之后普通调用不重复自动播放。字幕解释「减少重复输入 → 若实际计算需求下降，可能减少用电 → 可能降低冷却及发电用水压力 → 把资源留给自然」。右键可打开完整故事。它是虚拟成长，**没有实际节水、节电或植树数量的含义**。当前版本不从 token 数换算水资源升数。旧入口统一部署状态见仓库根目录 `CURRENT_PET.md`。

新版 `prepare_context` 和 `recall_memory` 返回 `context_reduction`，插件指引助手在回答旁显示一句提示。例如：

> TOMC：上下文估算 20,000 → 8,000 tokens，减少 12,000（60%）。仅比较上下文文本，不代表实际 API 或账单节省。

上面是示意数字。实际显示使用本次调用的计算结果；宿主决定最终如何展示，插件不能强制插入宿主状态栏。未生成可用上下文时会提示增大预算，不计作 100% 节省。内容变长时保留负减少量。

## 查看累计

可对助手说：

- “查看 TOMC 今天的上下文 token 减少统计。”
- “查看 TOMC 最近七天的统计。”
- “TOMC 累计帮我减少了多少上下文 token？”

对应调用 `get_usage_stats(period="today")`、`get_usage_stats(period="7d")`、`get_usage_stats(period="all")`。日期按 UTC；`7d` 指今天及前六个 UTC 日。查询本身不增加计数。统计从安装新版后的首次准备开始，无法追溯旧版本调用。

## 统计口径

每次成功完成的准备调用计一次，包括重复准备相同材料；这不是去重后的文档数或实际发出的模型请求数。原文指编译器规范化后的历史文本，整理后指返回的 memory，使用同一计数器。

累计减少量 = 可用准备的原文总量 − 整理后总量。累计减少比例 = 累计减少量 / 原文总量，不能平均每次的百分比。零减少和负减少均保留；没有可用输出的准备只计入排除次数，不进入 token 总量。不同计数器分别汇总，不混为一个总 token 数。

当前 MCP 路径使用词法估算，不是指定模型的真实 tokenizer。统计不包含任务文本、工具参数/返回封装、工具定义、宿主历史、额外模型调用或缓存。新增统计字段本身也有输入开销。只有应用实际用 memory 替代原文时，才可能减少对应模型请求的输入；此处不据此计算实际账单。

## 百分比与 Codex 剩余额度

详情中的上下文减少比例：`100 ×（所选时段原文总量 − 整理后总量）/ 原文总量`。它使用同一计数器的累计总量，不平均每次百分比。最近一次和结果气泡使用该次调用的比例。原文总量为零时显示“—”；负减少显示“上下文增加”，不同计数器显示“分口径”并在详情分别列出。接近但不足 100% 的值不会四舍五入成恰好 100%。

独立的 Codex 额度一行读取已登录账户的真实剩余额度，不能将上下文减少 92.1% 理解为额度省了 92.1%。模型、上下文、推理、工具、检索与缓存都会影响额度消耗，单靠输入长度无法推算，见 [官方用量说明](https://learn.chatgpt.com/docs/pricing)。美元与百分比均不等于账户额度节省。

挂件通过本机 Codex CLI 启动官方 `app-server`，每 60 秒异步调用只读 `account/rateLimits/read`，也接收额度更新通知，见 [官方额度接口](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。它使用现有登录，不发起推理、登录、额度重置或购买。未取得额度时显示“暂不可读”，清除旧值并等待重连；缺失或 null 不当作零。不同额度桶和周期分别显示，不相加；主行优先显示 Codex 桶的一项，其余在详情中列出。退出挂件会停止它拥有的额度辅助进程，不关闭其他 Codex/MCP 服务。

## 本地保存与隐私

统计与可选 notebook 使用同一个 SQLite 数据库，默认 `~/.tomc/memory.sqlite3`；遵循现有 `--store` 和 `TOMC_MEMORY_PATH` 设置。共享该数据库的客户端共享统计。保存每日数值汇总及最近一次准备的时间、计数器标识和 token 数字，不保存原文、任务、记忆本名称或逐条会话记录，不向服务器上传。

统计保留在 notebook 删除及插件卸载之后。不要为了清统计删除含有笔记的数据库。统计写入失败时，准备好的 memory 仍会返回，但提示本次未计入累计。纯 Python `prepare_context` 函数保持无持久化副作用；统计由 MCP 层记录。

## Windows TOMC · 省 token 小猫

这是可选的独立桌面宠物，不是 Codex 官方宠物或内部状态栏。平时只显示可拖动的毛绒猫头；点击展开上下文减少比例和独立的账户剩余额度。每次准备完成后，以数字事件触发处理上下文的示意动画，接着显示本次上下文减少或增加百分比，约六秒后收起。卡片是通用上下文示意，不读取或显示聊天内容。连续事件排队，队列有后续事件时缩短结果气泡停留时间。

点击展开的是 240 px 宽、标准离屏约 186 px 高的暖奶油色面板：顶部为 26×29 px 的委屈放空头像、固定名称 TOMC 和等级，下面用“今天 / 近七天 / 累计”切换上下文统计。主面板显示上下文减少或增加百分比、最近一次百分比，以及独立的 Codex 当前剩余额度。原始 token 数、计数器、准备次数、凝实度与成长进度收在“详情”中。打开面板不改变待机猫头的 72×80 px 尺寸，也不触发笑脸。测试模式始终标记“演示”；面板顶部 × 只收起统计，底部或右键菜单的“退出 TOMC”退出挂件。

四阶段门槛为 0 / 10,000 / 100,000 / 1,000,000 预计净减少 tokens。名称在所有阶段及多计数器状态下始终为 TOMC（省 token 小猫），只改变外观。外观是大眼睛毛绒猫头，始终没有身体和口袋；前三阶依次为浅色稀疏细绒、适中短绒、浓密厚绒与饱满脸颊，不带黄毛或金色额纹，究极版保留黄毛、皇冠及头两侧的翅膀。平时没精打采、委屈放空，眼神松弛无焦点，八字眉内高外低，避免凶相；只有处理上下文动画期间微笑。平时画布为 72×80 逻辑像素，动画时扩为 132×147；该尺寸指画布，第二阶角色会在其中缩小并移至左下。动画结束后角色绘制区域恢复 72×80 和委屈放空表情，结果气泡短暂显示后整体窗口也恢复紧凑大小。角色凝实度按 35% / 58% / 82% / 100% 连续增长。

第一、三、四阶分别让纸片飘落、两侧汇流、旋流吸入嘴里；第二阶以三次快速顶撞将大张散纸压紧并对齐为带绿色标题条的小卡片，再显示勾号并交付，不吞纸。四阶段时长分别为 2.4 / 3.4 / 2.8 / 3.2 秒。这些是准备完成后的示意动作，不表示实际计算进度；空闲时不循环播放，也不闪烁。

成长按同一计数器的历史最高净累计解锁；负减少仍扣减真实累计和当前进度，但不取消已解锁形态与凝实度。空输出不积累成长，多计数器不混合进化。外观养成不代表算法或模型能力增强。旧库可读，下一次准备时自动建立成长和事件表。

除每日和最近一次数字之外，数据库保存各计数器的最高净累计，以及最多 64 条近期数值事件（序号、时间、计数器、输入/输出数量、可用标记），用于顺序播放；不保存事件对应的原文或任务。关闭后再打开不会重播历史。超过短队列容量的极端突发仅保留最近 64 个事件，但每日累计仍包含全部调用。

先在专用 GUI 环境安装 `PySide6-Essentials`（或项目 `[widget]` 可选依赖），再运行 `python -m tomc.usage_widget`。可用 `--store` 指定与 MCP 相同的数据库。右键猫头选择“退出 TOMC”，或使用详情面板底部同名按钮，即可退出；详情顶部 × 只收起统计。桌面挂件的 × 在鼠标移入后显示。关闭宠物不会停止 MCP 计数。上下文统计仍从本地数据库读取；新增的真实额度通过官方账户接口获取，因此不能再将整个挂件描述为完全无网络读取。没有开机启动设置或电脑控制依赖。
